Most of this region is carried over unchanged, because it was the best-written part of this page. Three judgements in it are deliberate and are kept word for word: * The empty state names which catalog version found nothing. A bare "no results" invites the reader to conclude the CVE is safe, when what they have learned is only that one snapshot does not list it. * "ransomware: unknown" is worded as CISA not having established use, not as having ruled it out. * References are selectable text rather than links, because ION ships to air-gapped sites where an external anchor is a dead end that looks broken. The one defect: kevSearch's catch rendered into the ti-empty class, which is the no-results styling, so a failed lookup read as an empty catalog. That is the worst possible confusion for this panel in particular, since its whole purpose is to answer "is this being exploited right now". The status bar swaps out of band. One read answers both regions, because GET /api/kev returns the status block alongside the results, which is why the page passed `data.status` to kevRenderStatus rather than reading /kev/status separately. #} {# ---- the status bar, out of band ---- #}
