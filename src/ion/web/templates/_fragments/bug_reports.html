{# The submitted-reports card for /bug-reports. Replaces three innerHTML sites in bug_reports.html: the loaded table, the empty state and the load-failure message, plus the hand-rolled `esc()` and date formatter they needed. The markup is deliberately the same as what that JavaScript produced, so the page looks identical and the move is verifiable with tools/style_snapshot.py rather than by eye. The card chrome lives here, not on the page, so the header, the filters and Refresh have one definition. They also wrap BOTH states on purpose: with the failure as a bare alert, a filter change that failed swapped the filters away and left the panel with no way to change the filter back or retry short of reloading. The filters are the fragment's own hx-get, and it is the only request that knows which filters are on screen, so everything that reloads the list goes through it: `change` bubbles from the select and the checkbox, `click from:#bugs-refresh` is the Refresh button, and `bugs:changed` is what the page fires after submitting or syncing a report. The page shell requests this fragment once, on load, with the route's defaults. hx-include sends the filter values back, which is why the select and the checkbox render their state from `status` and `mine` rather than keeping it in the DOM: the swap replaces them.
