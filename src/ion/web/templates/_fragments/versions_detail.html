{# The version detail modal, for one version or for a pair being compared. Replaces the other two innerHTML sites in versions.html, both in `#modal-meta`: the metadata bar built by viewVersion() and the "Comparing versions" line written by showDiff(). Why the modal body is a fragment rather than client-side DOM work. Its metadata is the same three fields the row shows, with the same three rules behind them, so leaving it in JavaScript meant a second copy of each. The copies had already drifted once: viewVersion escaped the checkpoint name and not the message, and loadVersions escaped neither. The timestamp settles it. There is one honest rendering of a stored time, the `ts` macro, and JavaScript cannot reach it, so a client-side modal would have kept formatDate and left this page with two answers to "what time is this" while its list used the other one. The chrome is written once, around the branch, and the Close button renders in every state. bob_eval learned that the hard way: an error swap that returned a bare alert left the panel open with no way out but a reload. Close and the backdrop are the two built-in delegations in static/js/event-delegation.js, so neither needs a line of page script. Rollback is offered only when there is a version to roll back to. In the failed and missing states `rollback_to` is None, because a button that acts on a version the server could not read is a button that lies. #} {# `modal show`, not daisyUI's `modal modal-open`.
