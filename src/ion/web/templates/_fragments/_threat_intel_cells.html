{# Cells the actor and campaign result tables share. The two tables are not the same shape: actors have nine columns and campaigns seven, because actors carry an origin and a type list that campaigns do not. Only the cells that are genuinely identical live here, so the macros do not grow a parameter for every difference between the two and become harder to read than the duplication would have been. Everything here replaces a fragment of the string concatenation in searchActors and searchCampaigns, which built the same cells twice and had already drifted: the actor table rendered aliases with a "+N" more indicator and the campaign table silently truncated at three. #} {% macro origin(flag, name) -%} {# The flag and the country name travel together, keyed on the flag, which is right: both are derived from the same country code by country_mapper, so there is no state where one is known and the other is not. #} {%- if flag -%} {{ flag }} {{ name }} {%- else -%} - {%- endif -%} {%- endmacro %} {% macro aliases(values, shown=3) -%} {# `.slice(0, 3)` and a "+N" for the rest, which is what the actor table did. The campaign table dropped the "+N" and so told a reader that an entity with twelve aliases had three. Same macro now, so they cannot disagree again. #} {%- set all = values or [] -%} {%- if not all -%} - {%- else -%} {{ all[:shown]|join(', ') }} {%- if all|length > shown -%} +{{ all|length - shown }} {%- endif -%} {%- endif -%} {%- endmacro %} {% macro confidence(value) -%} {# Four states, not three. The page did `conf = a.confidence != null ? a.confidence : '-'` and then banded `conf >= 70 ? 'high' : conf >= 40 ? The colour is OpenCTI's own per-label colour, so it cannot be a class. #} {%- set all = values or [] -%} {%- if not all -%} - {%- else -%} {%- for l in all -%} {%- set colour = l.color or '#30363d' -%} {{ l.value }} {%- endfor -%} {%- endif -%} {%- endmacro %} {% macro watch_cell(kind, entity, can_manage, watched_ids) -%} {# Withheld entirely without observable:enrich, which is what POST /api/threat-intel/watches requires. The payload travels on the button as data-args rather than being looked up by index in a JavaScript array the server does not have. event-delegation.js JSON-parses data-args and applies it as arguments, so a one-element array hands the whole payload to watchActor as its first argument. #} {%- if not can_manage -%} Read only {%- elif entity.get('id') in watched_ids -%} {%- else -%} {# `.get`, not attribute access. Caught by a test that stubbed OpenCTI with minimal rows. #} {%- set payload = { 'entity_type': kind, 'opencti_id': entity.get('id'), 'name': entity.get('name'), 'description': entity.get('description'), 'aliases': entity.get('aliases') or [], 'labels': (entity.get('labels') or [])|map(attribute='value')|list, } -%} {%- endif -%} {%- endmacro %} {% macro detail_row_state(message, columns, tone='empty') -%} {# A detail row's own three outcomes, as the one cell a detail row is. #}
