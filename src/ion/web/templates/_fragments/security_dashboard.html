The severity select, the window select, Refresh and Export are not: they live in the page shell, outside this swap target, so a failed render cannot take away the control that retries. Block, quick-block, unblock and the status select are the four, and the API gates all four on that permission while gating the five reads on security:read. The Actions column goes with its buttons: a column of blanks is not information, so the header and the cells are gated together and the empty and failed rows span the columns that exist. A quick block of an address already on the block list is the one control whose effect depends on the record. The repository upserts, so it would replace a permanent block with sixty minutes. The server accepts that, so the control is not withheld; its title says what it would do.
