{# The tiles and the rule table are rendered whole by ion.web.ui.detection_health: the stat values, both bar cells, the flag badges, the drill-down rows and the unmapped note. They used to be a string concatenated in dhRender() and written in with innerHTML, which no stylesheet sweep could reach. hx-trigger="load" keeps the shell's first paint immediate and the figures arriving in their own request, which is what the fetch it replaces did. hx-include is on this request too, not only on Refresh: Firefox restores a select's value across a reload, so without it the first paint would report 90 days while the select read 7. hx-disinherit stops the drill-down buttons this panel renders from inheriting that hx-include. They carry the window baked into their own URL, and an inherited hx-include appends the select's live value after it, so the request went out as days=90&days=90 and FastAPI reads the last of a duplicate. Both copies agree today, because every path that changes the select also re-renders the panel. It is the drill-down answering for whichever window the select happens to hold, rather than the window the row above it was measured in, that this prevents. #}
